# 02 — User Manual

## 1. What Expedition Aurélio is

Expedition Aurélio is an offline-first documentary field-production workspace for recording, organizing and preserving cultural knowledge, craft practices, places and human stories. The phone is the field notebook and capture station. Local AI can assist with summarization and organization when the selected model is installed and supported. Internet features are optional.

## 2. Operating principles

1. **Capture first, interpret second.** Preserve original recordings and notes before asking AI to summarize them.
2. **Consent matters.** Explain the project and ask permission before recording interviews or identifiable people.
3. **Keep provenance.** Record who created an item, when, where, and from which original source.
4. **Offline is the baseline.** Field capture and local notes must not depend on a connection.
5. **AI output is a draft.** Verify names, dates, translations, quotations and cultural interpretations with people and reliable sources.

## 3. Home dashboard

The dashboard should provide access to:
- New field entry;
- Field journal;
- Media and interview records;
- AI laboratory / model library;
- Living Memory archive;
- Sync and backup status;
- Manual and troubleshooting.

If an item is not visible in the current build, treat it as a planned feature rather than assuming it is implemented.

## 4. Create a field entry

1. Open the app.
2. Select **New Field Entry**.
3. Add a concise title, for example: `Bamboo flute maker — workshop visit`.
4. Add the date and a short context note.
5. Add a location only with appropriate consent and only when it is safe to do so.
6. Add tags such as `craft`, `music`, `bamboo`, `interview`.
7. Save the entry.
8. Reopen it and confirm the content persists.

Suggested note structure:
- Context: what is happening?
- Person/community: how should the contributor be credited?
- Process: what steps or techniques were demonstrated?
- Vocabulary: local terms and preferred spelling;
- Uncertainties: what needs verification?
- Consent: what uses were agreed to?

## 5. Record an interview

Before recording:
1. Introduce yourself and the project.
2. Explain what will be recorded and how it may be used.
3. Ask whether audio, video, photographs and location may be captured.
4. Explain whether publication or online sharing is planned.
5. Record the person's preferred name and attribution, or their preference for anonymity.
6. Respect a refusal or request to stop.

During the interview:
- Ask open questions.
- Avoid leading questions.
- Leave pauses.
- Ask permission before recording sensitive or sacred material.
- Make a short field note when a name or term needs later verification.

After the interview:
- Confirm the recording saved.
- Create a descriptive title.
- Record consent scope and restrictions.
- Make a backup when safe and practical.
- Do not upload or share without the agreed permission.

## 6. Import media

For each photo, video or audio file:
1. Preserve the original file.
2. Import a copy into the project when the app supports it.
3. Give it a meaningful filename or title.
4. Link it to a field entry.
5. Record camera/device and capture date if available.
6. Add a short description and consent restrictions.

For Insta360 footage, retain the original 360 source files and project metadata. Do not overwrite originals with reframed exports. Use Insta360 Studio for reframing/export where appropriate, then attach the exported derivative to the same field entry.

## 7. Use local AI

1. Open the AI Laboratory.
2. Confirm a compatible model is installed.
3. Load the model.
4. Start with a small, non-sensitive test prompt.
5. Provide only the relevant text or transcript.
6. Ask for a structured draft, not an authoritative conclusion.
7. Compare the output against the original recording or notes.
8. Save the AI output as a derived document, linked to its source.

Example prompt:
> Create a neutral summary of this interview. Separate direct statements from your interpretation. List names and technical terms that need verification. Do not invent missing details.

## 8. Search the Living Memory archive

When archive search is available:
1. Search for a person, place, craft, technique or keyword.
2. Open the result and inspect its source links.
3. Check whether the result is an original record, transcript, note or AI-generated summary.
4. Verify the source before quoting or publishing.
5. Add corrections as a new version or annotation; preserve the original record.

## 9. Offline mode

Before leaving coverage:
- charge the phone and camera;
- check free storage;
- confirm model files are downloaded if local AI is required;
- open the app once while online to complete setup;
- test capture and save;
- enable airplane mode and test the workflow;
- carry a separate backup option.

While offline, do not expect web research, cloud sync, remote APIs or online model downloads to work. Queue sync for later rather than blocking capture.

## 10. Sync and backup

When a trusted connection is available:
1. Review queued items.
2. Check consent and sharing restrictions.
3. Select the destination.
4. Confirm the backup completed.
5. Verify a sample file can be opened from the backup.
6. Record the backup date and destination.

Do not assume a “sync complete” message proves every media file was uploaded. Verify counts, sizes or checksums where supported.

## 11. Export and archive

Keep a clear distinction between:
- original media;
- edited media;
- transcripts;
- AI summaries;
- research references;
- final documentary exports.

Use stable filenames such as:
`YYYY-MM-DD_location_subject_asset-type_sequence.ext`

Avoid placing passwords, private keys or unnecessary personal data in filenames or metadata.

## 12. Data ownership and deletion

Before deleting an entry, understand whether it has linked media, transcripts, AI derivatives or synced copies. If the app supports deletion, confirm the scope and backup status first. A local deletion may not delete remote copies, and remote deletion may not erase copies held by collaborators.
